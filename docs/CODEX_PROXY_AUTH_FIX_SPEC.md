# Provider-specific Codex authentication correction

## Problem and source cause

Base Orchestra 0.12.1 (`8457bd6`) and Polygram 0.46.1 (`06ba700`) retain the reviewed Codex 0.167.2 runtime and current Claude changes. Polygram's proxy renderer sets `requires_openai_auth = true`; Orchestra preflight/receipt and Polygram catalog then require a ChatGPT account even when inference uses CLIProxy. This blocks the intended VPS proxy deployment unless unrelated native credentials are provisioned. The user explicitly corrected that requirement: CLIProxy owns upstream auth; no Mac auth transfer or native login.

Pinned official source `openai/codex` tag `rust-v0.167.2` establishes:

- `model-provider/src/provider.rs::account_state` returns `account: null, requiresOpenaiAuth: false` for the external provider, independent of native account presence.
- `model-provider/src/auth.rs::resolve_provider_auth` selects the configured provider bearer before native auth; `bearer_auth_for_provider` accepts the existing private bearer mechanism.
- `model-provider/src/models_endpoint.rs::supports_api_key_models` and `models-manager/src/manager.rs::should_refresh_models` leave this custom provider on bundled model metadata. `model/list` is runtime capability/catalog evidence, not external credentials or entitlement validation.

Current official guidance: https://learn.chatgpt.com/docs/config-file/config-reference and https://learn.chatgpt.com/docs/app-server; pinned source is authoritative for the exact runtime. The existing CLIProxy v8.0.4 route authenticates its own client bearer and owns upstream credentials; no native client token is necessary.

## Smallest correction

1. Polygram renders only its already supported named, loopback Responses CLIProxy provider with `requires_openai_auth = false`, retaining private key-file checks, exact configuration hashing, deployment fingerprint fencing and no fallback.
2. Orchestra derives auth expectations from the already attested `expectedConfig.modelProvider`; add no configuration option, auth framework or provider discovery. Native `openai` requires ChatGPT plus `requiresOpenaiAuth: true`. CLIProxy requires exactly null account plus `requiresOpenaiAuth: false`. Missing/malformed/mismatched fields fail before model discovery. The account/read wire projector must require an own `account` field and accept explicit null, not normalize omission to null. This is a local fail-closed requirement matching the pinned Rust emitter and TypeScript type; generated JSON Schema alone does not require the field.
3. Preserve native public receipt and spawn-profile identity. External preflight uses the distinct truthful state `auth: { authenticated: false, accountType: null, requiresOpenaiAuth: false }`: no OpenAI account was authenticated and external bearer validity has not been inferred from config/catalog. The existing attestation identifies `cliproxyapi`; spawn identity uses null account type alongside that exact provider/config identity. Receipt creation validates the appropriate tuple and retains the successful-result WeakSet provenance requirement.
4. Polygram's catalog accepts/project-preserves exactly that provider-specific tuple, selected against the expected profile and authenticated branded Orchestra receipt. It never relabels an external provider as ChatGPT or claims a catalog is external entitlement proof. Native missing auth and cross-provider receipt/account mismatches still fail and invalidate cache.
5. Amend the prior Polygram minimal spec's CLIProxy paragraph and affected runtime compatibility docs to replace the obsolete native-login requirement. Preserve existing limited/trusted policies, skills/instruction binding, native mode, hooks, launcher and process lifecycle contracts. No production configuration, services, login stores, package pins or release versions change here.

Alternatives rejected: provision native ChatGPT credentials (contradicts requested routing and transfers unrelated auth); bypass all account checks (loses provider mismatch fencing); add a generic provider-auth framework or new login mechanism (unnecessary); call model/list an authenticated entitlement check (false for the pinned runtime); add a paid turn to ordinary preflight (unnecessary recurring cost).
